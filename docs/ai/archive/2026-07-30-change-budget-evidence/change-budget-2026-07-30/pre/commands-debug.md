# 系统化调试

报错 / 失败：$ARGUMENTS

不允许"试着改改看"。与全局"同一修复连续两次失败即停下报告"硬规则衔接。

**铁律：没定位根因前，不许动手改。**「先试着改 X 看会不会好」是头号反模式。

四阶段按序走：

1. **根因调查**：逐字读 error + stack trace（含行号）；能否稳定复现？最近改了什么？多组件系统在每层边界加诊断 log（打印入参/出参/关键状态），先确定"哪层断的"；沿数据流向上追坏值从哪来，追到源头，不在症状处堵。
2. **模式对照**：找一处能正常工作的相似代码，完整读（不跳读），逐条列出 working 与 broken 的每个差异——根因常在差异里。
3. **假设与验证**：写下"我认为根因是 X，因为 Y"；一次只改一个变量验证；没中就换假设，不堆多个 fix。
4. **实现修复**：先写能复现该 bug 的失败用例 → 只针对根因改最小一处 → 跑验证（回归红→绿）。

**反复尝试仍失败 → 停手**：第二次失败就停，回阶段 1 重做根因调查，不继续堆 fix；若根因指向"问题在底层设计/假设"，判为架构问题、上报人类。

**红旗（出现即代表偏离根因调查，借口 → 现实）**：

| 借口 | 现实 |
|---|---|
| "先快速修一下，回头再查" | 没根因的修复只是把 bug 移位，回头不会来 |
| "改一下 X 试试能不能好" | 这是猜不是调试；先定位再改 |
| "多改几处一起跑测试看" | 一次只改一个变量，否则分不清谁起作用 |
| "应该是 X 的问题，我修 X"（没验证） | 未验证的假设不是根因 |
| "再试最后一次"（已试 2 次以上） | 回阶段 1，别堆 fix |

> 调试期任何改动同样受声称完成纪律（见 `/implement`）约束：说"修好了"前复现用例必须真的红→绿。

## 回归安全修复协议（Review-Fix Protocol）— 修 Reviewer blocking / 任何"修 A 别破 B"时强制走

> 针对的失败模式：只盯触发点做局部修 → 当前案例过、破坏别的场景 → 下轮再局部修 → 补丁越滚越多、到第 N 轮才想起查架构。**语言模型"复盘说吸取了教训"≠ 真改了行为**——本协议只认产物、不认叙述。

**改任何 fix 前先产出（不产出不许改）：**

1. **Blast-radius 枚举**：要改的字段/断言/路径——grep 出**所有生产者 + 所有消费者**；列出**完整值域**（枚举全集 / null / 空 / 边界 / 极值 / 各生产路径 / 各消费路径）。修复要对**全集**成立，不是只对被报案例。
2. **回归产物 + 跑全量相关套件**：先写复现被报案例的失败用例（红）→ 只针对根因改最小一处 → 该用例红→绿，**并跑整组相关测试**（不是单个案例——"修 A 破 B" 只有把 B 也跑了才暴露）。声称「回归用例有效」时守护证据按 `AGENTS.md` → 守护有效性装置产物化（结构化产物，非对话叙述）。
3. **最小根因修复**：review-fix 是 scoped 修复（此处"最小"是**实现范围**纪律，与"选方案要整体最优"不冲突）——**不是**趁机大重构/引入新抽象；大补丁 = 连锁破坏，正是本失败模式。

**跨轮硬停（规则见 `AGENTS.md` → Fix-Loop 计数；记进 HANDOFF 的 Fix-Loop Counter）：**
* streak 只由 **Reviewer 判定 `caused_by_last_fix: yes` 的 Product/Verification Blocking** 递增（**Author 不得自填来源**）；9A/9B 同一问题不重复计；来源争议交人类。
* **streak 连续达 2 → 立即停止编码**，只能：**回退 / 重新拆任务 / 请求人类批准架构升级**；**禁止"再试一轮"**（未获人类确认不得继续）。不许一路补到第 6 轮才"开始修类"。
* 根因是**架构/抽象错了** → 停 + 重规划 + 人类拍板，**既不在循环里继续打补丁、也不在循环里偷偷大改**（扩架构/新模块/改公共接口一律停 + 重 plan，见 AGENTS review-fix 最小范围）。

**禁止"复盘即完成"**："我理解了 / 吸取了教训 / 这次会注意"一律零分——**只有 blast-radius 枚举 + 回归测试（复现用例红→绿 + 全量绿）算数**。

**卡住 → 回到最后可靠提交 + 全新上下文（切断长对话路径依赖）：** 同一处 fix 失败 2 次后，**别让当前上下文继续在累积补丁上修**（它已锚定在自己编的架构故事上）——**先回退到最后可靠提交**（丢弃层层累积的旧补丁与旧解释），再派一个**全新上下文的 sub-agent**，只喂：原始 TASK_BRIEF 验收条件（逐字）+ 批准计划 + 基线与当前干净 diff + 失败案例 + blast-radius 枚举；**不给对话历史、不给前几轮补丁叙述**。让它从原始需求重新推。（sub-agent 继承主对话模型、不降级，见 CLAUDE.md；判"能力回退 vs 上下文锚定"见 `~/.claude/workflow/AB-model-diagnostic.md`。）
