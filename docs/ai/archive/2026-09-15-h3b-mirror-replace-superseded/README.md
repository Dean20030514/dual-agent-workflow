# 2026-09-15 · H3-B「mirror-replace 写入路径」—— 已取代（SUPERSEDED）

> 本目录归档的是**被人类裁决放弃的方向**的规划产物，保留作历史与判据来源，**不是当前对齐目标**。

## 为什么归档

`install.ps1` 的写入路径原本要恢复 **mirror-replace** 语义（删除"源树没有且非白名单"的本机文件），并配 AC1–AC9 全套 Critical 闸门（备份、白名单段级化、计划==执行、`[SEAL]` 封存、恢复演练、人类真部署产物…）。这套方案跑了 **3 轮 9P 计划审**（round 3 = 修订后可批准）仍未进入实现。

**人类 2026-09-15 裁决**：放弃删除语义，改为 **只增/只更新**（覆盖前逐文件备份、**永不删除**、本机独有内容只报告 `[STALE]`），并**降档 Routine**。理由：删除是这条线上全部风险与全部仪式成本的来源，而它买到的只是"清理残留"这一点额外收益。

裁决同时明确：**若将来仍需要删除能力，属新任务，须重新立项**——不要在后续改动里顺手加回。

## 本目录里仍然有效的结论（被后续实现复用）

1. **PROBE-D**（`IMPLEMENTATION_PLAN.md` §8）：白名单只按 `*.bak-*` **叶名**判定时，源树自带同名目录会让目标侧本机独有文件被判 `[DELETE]`。该缺口已按"**任一段**命中"修掉。
2. **PROBE-B**：`Remove-Item -Recurse` 会吞掉白名单子树 ⇒ 实现里**没有任何递归删除**。
3. **PROBE-E**：live-only **空目录**确实进 `[DELETE] (dir)` 行 ⇒ 只增/只更新语义下它是"报告面"的一部分。
4. **PROBE-C**：同秒同名备份会嵌套 ⇒ 备份名带 4 位 guid。
5. 备份策略：**只备份被覆盖的单文件，不做整树备份**（整树备份会复制凭据）。
